# Verify the session loop (guide 6.3, 6.4, 2.3)

Shared launch, doctor, evidence and cleanup: [verify](../verify/SKILL.md). Decision records:
[ADR 0005](../../../docs/adr/0005-loop-rows-wake-obligations-sweeper.md),
[ADR 0006](../../../docs/adr/0006-store-same-rows-four-owners.md) and
[ADR 0007](../../../docs/adr/0007-tools-schema-is-data.md). The statechart in
[docs/statecharts/session-loop](../../../docs/statecharts/session-loop/README.md) is the model
of this subsystem; read it before you change `actor.ts`, `loop.ts` or `lineage.ts`.

Every blocking call of upstream's loop is a row and a return here: write the pending row and
its wake obligation, commit, then send. A new owner reads the row and continues.

## Sub-features

- **Schema and migration** (`schema.test.ts`, `migrate.test.ts`): upstream's tables at schema 32; forward-only migration on first read.
- **Admissions** (`admissions.test.ts`): `session_admissions` as the inbox, deduplicated, `queued → started → terminal`, `unknown` on owner loss.
- **Model step** (`model.test.ts`, `src/model/`): the scripted model and the recorder that golden uses. The `pending_call` row and its resend with the same `call_id` are tested in `faults/src/loop`.
- **Tools** (`tools.test.ts`, `src/tools/`): clarify, todo, terminal through the executor contract; persist the tool-call turn before any tool runs; results in call order.
- **Compaction** (`lineage.ts`): the two-commit move to a child session at 50%, the hygiene check at 85%, the unresolved tail copied into the child.
- **Prompt** (`packages/prompt`): the builder against upstream fixtures, the compressor.
- **Providers** (`packages/providers`): chat_completions, anthropic_messages, codex_responses, bedrock_converse; SSE streams; error text; key rotation; fallback on 429; reasoning blocks kept for the rebuild.
- **Loop fault tests** (`packages/faults/src/loop`): D1, D7, cancellation at each point, the compaction race, handoff, replay, upgrade under new code with old rows.

## How to get to it (user POV)

A user message becomes a `session_admissions` row; the actor starts a turn. There is no
command that runs one turn by hand. The golden CLI is the closest: it plays a script (user
inputs and model answers) through the real actor on the Node simulator.

## Driving it with verify.ts

```sh
bun .claude/skills/verify/verify.ts run loop
```

Runs 24 test files (407 tests on bun), then `packages/golden/src/cli.ts check` on
`plain-reply`, `one-tool-call`, `parallel-tools`, `clarify-sequential` and `compaction-50`,
which must print 5 `same` lines. Proof: `PASS loop ... 1/1 drives`.

If your change alters what the model is sent or which rows are written, also run
[verify-golden](../verify-golden/SKILL.md) (all 20 scripts) and
[verify-faults](../verify-faults/SKILL.md).

## Gotchas

- A step must read the current session inside its commit, not from a snapshot taken before the fetch. The old code lost a reply into a retired parent when a compaction landed during a model call (`faults/src/loop/compact-race.test.ts`, rule `NoLostMessage` in the statechart).
- There is no local "sent" flag. A pending row with no result means "may have been sent"; never add a flag to skip the retry.
- A tool call and its result are never split across a compaction.
- The model is scripted. No test calls a real provider, so provider authentication against a live endpoint is not shown.
- `profile-actor` has no test file of its own; `faults/src/loop/profile.test.ts` and D12 cover it.
- If you change the TLA+ spec or the transitions, regenerate the chart as its README says. The chart is not regenerated by this skill.
